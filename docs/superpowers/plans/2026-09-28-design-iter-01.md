# Design iteration 01 — implementation plan

**Spec:** `docs/design/ITERATION_LOG.md` → "Iteration 00 — Baseline" (its
critique + "Next iteration" list) and `DESIGN.md` (the design contract).
**Goal:** fix the three P0s and the two top P1s from the baseline critique.

## Global Constraints (bind every task)

- Only edit files under `dashboard/` and `scripts/screenshot.mjs` (Task 2 only).
  **Never** edit anything in `commerce-agent/src/` or `catalog-server/`.
- Zero runtime dependencies, vanilla JS ES modules, no build step, no framework.
- Colours/radii/spacing come from CSS custom properties in
  `dashboard/css/tokens.css` — no new hard-coded hex in CSS (canvas JS may
  read tokens via `getComputedStyle`, or keep the module's existing defaults).
- Both themes (dark + light) and both viewports (390×844 mobile, 1440×900
  desktop) must look right. Respect `prefers-reduced-motion`.
- Honesty: nothing on screen may show data the server doesn't have.
- DESIGN.md rules: touch targets ≥ 40px on mobile, text ≥ 12px (11px mono
  labels allowed if ≥ 4.5:1), visible focus, 4px spacing grid, tabular
  numbers for money.
- Match the surrounding code style: the `h("tag.class#id", props, ...kids)`
  helper from `dashboard/js/ui/dom.js`, 2-space indent, short comments only
  where the *why* is non-obvious.

### Task 1: Mobile bottom tab bar

**Problem (baseline P0):** at 390px the top nav's links overflow — "Mandates"
is cut mid-word and "Agents" is unreachable without discovering a hidden
horizontal scroll.

**Files:** `dashboard/css/components.css` (nav section), `dashboard/css/base.css`
(`.shell` inset), `dashboard/index.html` only if markup must change,
toast positioning in `components.css` if it collides.

**Do:**
- At `max-width: 640px`, render `.nav-links` as a fixed **bottom tab bar**:
  full width, 4 equal columns, height 60px plus
  `env(safe-area-inset-bottom)` padding, `--surface-1` background with a
  `--line` top border (solid, no backdrop-filter — see the existing nav
  comment about the Chromium paint hazard), each link a ≥ 44px tall
  centred target. Active link: `--iris` text colour and a 2px `--iris`
  indicator bar on the **top** edge (replace the bottom underline used on
  desktop at this breakpoint).
- The `.nav` element is `position: fixed` with no transform, so a
  `position: fixed` child resolves against the viewport — CSS-only is
  preferred; change markup only if CSS alone can't do it.
- Give `.shell` a bottom inset equal to the tab bar height at that
  breakpoint so the last content isn't hidden behind the bar.
- Make sure toasts (and any bottom-anchored UI in `components.css`) sit
  above the tab bar at that breakpoint.
- The top bar at ≤640px keeps: logo (no wordmark — already hidden),
  theme toggle, DEMO MODE pill.
- 641–820px: the existing horizontal-scroll behaviour stays; verify at
  768px wide that all four links are fully visible without scrolling.

**Accept:** at 390 all four destinations are visible and tappable in the
bottom bar in both themes; the active one is clearly marked; no page's
bottom content is covered; desktop nav unchanged.

### Task 2: Fix mobile overflow in every view

**Problem (baseline P0):** at 390px, content runs off the right edge on
Mandates (persona cards, balance panel, credential JSON), Agents (every
panel), Console (`.pstep`), Landing (`.path-card`).

**Files:** `dashboard/css/views.css`, `dashboard/css/components.css`,
`dashboard/css/base.css`, `scripts/screenshot.mjs`.

**Do:**
- Find root causes — grid/flex children missing `min-width: 0`, fixed
  widths, `white-space: nowrap`/`pre` blocks without wrapping, long
  unbroken hashes — and fix them. Code/JSON blocks: either wrap
  (`white-space: pre-wrap; overflow-wrap: anywhere`) or scroll inside
  their own box (`overflow-x: auto; max-width: 100%`). Long hashes and
  ids: `overflow-wrap: anywhere`.
- **Do not** paper over it by adding `overflow: hidden` to panels or page
  containers — that hides clipped content instead of fixing it.
- Improve the overflow check in `scripts/screenshot.mjs`: an element should
  be flagged only if it pokes past the viewport **and** no ancestor between
  it and `.shell` clips or scrolls horizontally (`overflow-x` of `auto`,
  `scroll`, `hidden` or `clip`). Also skip `canvas` elements. Keep the
  existing report format.

**Accept:** a shots run lists **zero** "content wider than viewport"
problems; the mobile PNGs for Mandates, Agents, Console and Landing show
every panel fully inside the viewport in both themes; desktop unchanged.

### Task 3: Make the 3D hash-chain truthful

**Problem (baseline P0, honesty):** `dashboard/js/gl/chain3d.js` always
draws a fixed number of blocks (`count: 6` on Landing, `count: 8` on
Ledger), even when the ledger has 0 records. The Ledger view says
"chain height 0" beside 8 linked blocks. For a product whose pitch is
"numbers on screen are real", this is a credibility leak.

**Files:** `dashboard/js/gl/chain3d.js`, `dashboard/js/views/ledger.js`,
`dashboard/js/views/landing.js`, `dashboard/css/views.css` (caption styles).

**Do:**
- `createChain3D(canvas, opts)`: add `opts.height` (the real number of
  records; default 0) and `opts.max` (how many blocks to draw at most;
  default the old `count`). Draw `min(height, max)` blocks.
- `height === 0`: draw a single **genesis placeholder** — a dashed, low-
  alpha outline cube, no link, no travelling spark. It still rotates
  (unless reduced motion).
- `addBlock()` on an empty chain replaces the placeholder with the first
  real block; after that it grows until `max`, then shifts as today.
  Also expose `reset()` (back to the empty placeholder) and make
  `frameOnce()` (reduced-motion path) handle both states.
- Ledger view: create the chain **after** events load, passing the real
  height (`last event seq + 1`, or 0). Overlay reads `chain height N`;
  when N is 0 also show a caption: "No records yet — start a session in
  the console to write the first one."
- Landing hero: get the real height from `store.get("metrics")?.chain?.seq`
  (the server's `/metrics` includes `chain: { seq, hash }`, seq −1 when
  empty; height = seq + 1) — if metrics aren't loaded yet, fall back to
  `api.verifyChain()` or 0; don't block first paint on it. Badge text:
  `hash-chained ledger · N records · live`, or
  `hash-chained ledger · empty · waiting for the first record` at 0.
  Keep the badge live as SSE audit events arrive.
- If a demo reset is observable in the dashboard (check `js/sse.js` /
  `js/app.js` for a reset event or a seq going back to 0), call `reset()`.
  If there is no such signal, don't invent one — note it in your report.

**Accept:** fresh server (0 records): Ledger and Landing each show one
dashed genesis cube with the empty caption/badge. After a real event
(e.g. start a session and send "gifts under 1500" through the Console, or
POST to an endpoint the existing UI uses that writes an audit record),
the chain shows exactly as many blocks as records (up to max).
Screenshots in both themes; reduced-motion frame renders too.

### Task 4: Honest, useful Ledger empty state

**Problem (baseline P1):** with 0 records the Ledger shows a **green**
`--ok` banner ("Ledger is empty — nothing to verify yet."), which reads as
success; "Verify chain" is enabled though there's nothing to verify; the
feed says "No records match this filter yet." with no next step.

**Files:** `dashboard/js/views/ledger.js`, `dashboard/css/views.css`
(and `components.css` only if a shared style is needed).

**Do:**
- Add a neutral **empty** state for `.chain-status` (surface `--surface-2`,
  border `--line`, text `--text-dim`, no semantic colour). Use it whenever
  the chain has 0 records. The initial "verifying…" state is also neutral,
  not `.ok`. Keep `.ok` / `.bad` for real verification results.
- Disable "Verify chain" while the ledger is empty, with a `title`
  explaining why ("Nothing to verify until the first record is written");
  re-enable it when the first SSE audit event arrives.
- Feed empty state when the filter is **All** and there are no records:
  a short title "No records yet", one dim line "Every Gate decision,
  hold and payment lands here the moment it happens.", and a secondary
  button "Open the console →" that navigates to `/console` (use
  `navigate` from `js/router.js`). With another filter active and no
  matches: "No <label> records yet." (e.g. "No blocked records yet.").
- Task 3 (already done before this task) changed how this view creates
  the chain canvas — build on its code, don't revert it.

**Accept:** fresh server: neutral banner, disabled verify button with
tooltip, feed empty state with working CTA, in both themes and both
viewports. After one event: banner verifies to `.ok`, button enabled,
feed shows the record.

### Task 5: Console — anchored stepper, suggested prompts, aligned input

**Problems (baseline P1 + P2):** the PLAN→SETTLE stepper floats above the
grid with no anchor and duplicates the chat panel's "plan · act · observe
· reflect" label; the empty chat pane is ~400px of dead space with no
obvious first action; the input row's mic button (~34px) doesn't match
the input and send button (~42px).

**Files:** `dashboard/js/views/console.js`, `dashboard/css/views.css`,
`dashboard/index.html` (cache-buster only).

**Do:**
- Move the `#pipeline` stepper **inside** the chat panel, directly under
  its `panel-head`, and remove the now-redundant
  "plan · act · observe · reflect" label from that head. Keep the
  stepper's ids/classes and `setStage` behaviour working.
- In the empty chat state (`#chat-empty`), under the existing explanatory
  copy, add three **suggested prompt** chips (buttons, ≥ 40px tall on
  mobile, wrap onto multiple lines at 390px):
  1. "Gifts under ₹1,500"  → sends `gifts under 1500`
  2. "Buy the candle duo" → sends `buy the candle duo`
  3. "Try to spend ₹5,000" → sends `buy something for 5000` (shows the
     Gate refusing on the ₹2,000 Gift-shopper mandate)
  Clicking a chip: if no session is active, start one with the currently
  selected mandate first (reuse the existing `startSession` path and wait
  for it), then put the text in `#chat-input` and send it through the
  existing `doSend`. The chips must also remain available after the
  session starts, until the first message is sent.
- Input row: give the text input, mic button and send button one shared
  height of 44px, vertically centred icons; the mic and send buttons are
  44×44 squares.
- Bump every `?b=22` cache-buster in `dashboard/index.html` to `?b=23`.

**Accept:** desktop and mobile Console shots show the stepper inside the
chat panel, the chips in the empty state, and an aligned input row in both
themes. Interactive check (Playwright): clicking "Gifts under ₹1,500" on a
fresh page starts a session and a user message bubble appears in
`#chat-log` (the agent's reply may be a "couldn't reach my reasoning
model" fallback in this sandbox — that's fine; the UI flow is what's
under test).
